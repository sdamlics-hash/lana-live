# Проверка защищённого канала перед Samsung

Это проверка доступности HTTPS и Bearer-авторизации, а не запуск Ланы на сервере. Скрипт не вызывает OpenAI, не пишет память и не проверяет микрофон. Он отправляет только два GET /v1/status: без ключа ожидает 401, с ключом — точную схему текущего сервера Ланы. Штатная проверка сертификатов включена, редиректы запрещены. Ключ не выводится.

После независимого развёртывания тестового сервера за доверенным TLS-шлюзом:

```text
python staging/check_connection.py --url https://ВАШ-ДОМЕН-ЛАНЫ
```

Токен приложения передаётся через уже настроенную переменную LANA_API_TOKEN; это НЕ OPENAI_API_KEY. Не вводить секрет в аргументы команды и не загружать его в GitHub. Без действующего токена проверка завершится отказом. Поддержки отключения проверки сертификата нет.

По-прежнему не менять loopback 127.0.0.1 на публичный 0.0.0.0. Публичный канал требует отдельного TLS/VPN-шлюза. Доверенный сертификат удостоверяет сервер, Bearer-токен — клиента. Токен защищает один изолированный личный сервер; это не многопользовательская схема.

Следующие этапы: фактический TLS-шлюз на отдельном сервере, этот тест против него, ограниченный настоящий диалог, потом Samsung и измерение задержек. Успех этого скрипта не означает доступ к истории ChatGPT, готовность платной модели, работу памяти или 24/7.

Локальные тесты включают реальный TLS-сокет с временным сертификатом: недоверенный сертификат и неверный токен отклоняются, специально доверенный тестовый сертификат проходит. Тест не обращается к внешней сети и не отключает проверку TLS.
