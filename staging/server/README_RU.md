# Изолированный сервер Ланы — пакет для развёртывания

Статус: подготовленные файлы, НЕ работающий сервер. Установленная APK не меняется. Сначала проверить VM и выбрать контролируемый домен. Нет доступа к истории ChatGPT. Диалог через OpenAI — отдельный сервис.

## Что изолировано

- Отдельный непривилегированный пользователь lana-staging, каталог кода /opt/lana-staging и база /var/lib/lana-staging/lana.sqlite3 (0700).
- Python API слушает ТОЛЬКО 127.0.0.1:18787. Перед запуском проверить, что порт свободен. Не менять существующие сервисы, базы, firewall или роботов.
- TLS завершает Caddy. Пример не работает без настоящего DNS-имени и доверенного сертификата. Отдельный блок добавляется к существующей конфигурации, а не заменяет её. Не открывать порт 18787 наружу.
- Снаружи доступны только GET /v1/status и POST /v1/chat, оба требуют токен приложения. /v1/tasks, /frame и остальные пути не публикуются.
- systemd запрещает повышение привилегий и запись вне собственного StateDirectory; корневой код должен принадлежать root, не пользователю сервиса.

## Секреты и стоимость

/etc/lana-staging/secrets.env должен принадлежать root:root и иметь права 0600; директория /etc/lana-staging — 0700. Два разных секрета: LANA_API_TOKEN (случайный токен приложения >=32 символов) и OPENAI_API_KEY (серверный ключ провайдера). Не вставлять значения в GitHub, APK, URL, переписку, аргументы команд или демонстрационные логи. Настоящий OpenAI-ключ пока не предоставлен этой среде; этот пакет его не создаёт и не копирует.

В service заданы небольшие стартовые лимиты 20 попыток в сутки и 10 на разговор в час; ошибочные платные попытки тоже учитываются. Это предел количества запросов, НЕ гарантированный денежный бюджет. Дополнительно настроить проектные ограничения провайдера перед настоящим запуском. Один запрос не делает рекурсивных вызовов. Не включать таймеры, фоновые ИИ-циклы или очередь daemon на этом этапе.

## Приёмка

1. Проверить VM: свободные CPU/RAM/диск, Python, порт 18787, DNS/TLS и существующий веб-сервер. Сохранить текущую конфигурацию до правок.
2. Установить только проверенную ветку кода в отдельный каталог. Создать пользователя без входа. Секреты передать по защищённому каналу; не запрашивать их в чате.
3. Проверить unit через systemd-analyze verify и конфигурацию через caddy validate. Не считать локальную синтаксическую проверку доказательством запуска.
4. Запустить отдельный service и проверить отсутствие токенов/текста разговоров в диагностике. Затем применить отдельный доменный блок Caddy без перезаписи соседних сайтов.
5. Запустить staging/check_connection.py с настроенным токеном. Без авторизации ожидается 401, с авторизацией — JSON статуса. Он не расходует OpenAI API.
6. С явным лимитом выполнить ОДИН настоящий вопрос к /v1/chat, проверить ответ и повторное чтение локальной памяти. Далее Samsung: два-три последовательных вопроса, стоп/новый старт, сеть, 20 минут диалога и задержка. Фон/экран выключен проверяются отдельно.

Откат: остановить и отключить только lana-staging, убрать только добавленный доменный блок после проверки общей конфигурации. Базу и локальные резервные копии не удалять; торговые службы не трогать.
