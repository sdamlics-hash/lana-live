# LANA — защищённые ответы Android ↔ HTTPS (25.10.2026)

## План и критерии готовности
Проверить все три сетевых клиента Android (status, chat, speech). Убрать риск неограниченного чтения JSON-ответа в память, не менять API-контракт и подпись APK. **Критерий:** сервер, приславший бесконечный поток или завышенный ответ без Content-Length, не должен заставить приложение выделять неограниченную память. Некорректный UTF-8 отклонять, а не превращать в выдуманный ответ.

## Выполнено в изолированной ветке
- `LanaCoreClient.checkStatus`: ограничение 8192 **байт до декодирования** вместо `readText()` + поздняя проверка символов.
- `LanaChatClient.ask`: ограничение 12000 **байт до декодирования** вместо `readText()` + поздняя проверка символов.
- `LanaSpeechClient.audio` уже читает MP3 блоками с лимитом 8 МБ, поэтому его не меняли.
- Общий `LanaHttpBody.readUtf8Bounded` копируется в создаваемые Android-проекты через V3.4 patcher, поэтому достигает и V3.5/V3.6/V4.4.
- Добавлены реальные Kotlin/JUnit проверки границы лимита, русской UTF-8 строки, некорректной кодировки, бесконечного InputStream, пустого ответа и потока без прогресса; Python проверки генерации APK.

## Проверки и независимое подтверждение
**Ожидается GitHub Actions:** V3.4 Bridge Preview, V3.5 Voice Preview и V3.6 native/emulator. Успешная сборка — не проверка реального HTTPS-сервера и не тест физического Samsung. Тесты сети используют только контролируемые локальные потоки; реальные ключи не требуются.

## Риски и ограничения
- Изменение относится к защитному чтению ответа, не к TLS-подключению и не к постоянному фоновому микрофону.
- `LanaCoreClient` по-прежнему требует HTTPS, запрещает редиректы и не хранит ключ. Для реальной VM требуется отдельная проверка доверенной цепочки сертификата, маршрута и полномочий.
- Упрощённая защита не является денежным лимитом. PR #17 добавляет глобальный часовой предел, PR #35 защищает серверный OpenAI-редирект; оба изменения ещё требуют интеграционной приёмки в актуальной ветке.
