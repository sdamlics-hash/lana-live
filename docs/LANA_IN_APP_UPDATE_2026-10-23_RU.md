# Обновление Ланы из приложения

Кнопка «Обновить Лану» в разговоре рядом с образом. Установленная версия отображается рядом.

Поток: явное нажатие → проверка опубликованной версии → подтверждение скачивания → скачивание APK в закрытый кеш → размер/SHA-256/пакет/версия/подпись → системный установщик. Обновление только поверх ai.dreibus.lanalive.stablevoice с той же подписью; откат не устанавливается. Данные приложения не удаляются.

При первом запросе установки Android может потребовать разрешить этому источнику установку приложений. После возврата в Лану скачанный APK проверяется заново и передаётся установщику. Системное подтверждение установки не обходится. Разрешение может быть отозвано пользователем или ограничено политикой устройства. Лана не использует root/device owner/автонажатия.

GitHub Actions после тестов и проверки подписи публикует релиз lana-stable-<versionCode>, содержащий только подписанный APK и lana-update.json. Постоянный ключ подписи не публикуется в релизе. Метаданные указывают точную неизменяемую версию URL. Запросы обновления не передают ключи сервера или GitHub-токены. HTTPS redirects разрешены только к GitHub/CDN. FileProvider открывает только каталог кеша обновлений; внешнее хранилище не требуется.

Ограничения: первое обновление с этой функцией ещё ставится вручную по прямой ссылке; следующие запрашиваются кнопкой. Установка на Samsung, возврат из разрешений, отмена установки и повторная установка ещё требуют проверки на устройстве. Процесс загрузки не является фоновым сервисом; после уничтожения Activity может потребоваться повторное нажатие. После скачивания проверенный кеш может быть использован повторно. Нет обещания бесшумной установки.

Проверки: разбор/валидация метаданных покрыт JVM-тестами; общая сборка компилирует установщик и манифест; после публикации нужно сравнить метаданные с реальным APK. Проверка будущего более нового релиза кнопкой возможна после установки текущего.
