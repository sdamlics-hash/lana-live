# DREIBUS AI LANA — архитектурная ревизия и единый план (25.10.2026)

## Проверенный объём
- Прочитаны исходники, требования, CI и реестр GitHub репозитория lana-live (211 файлов), репозиторий lana-server-ops, опубликованные релизы (1043 — последний релиз на 25.10) и отчёты тестов, доступные через подключённый GitHub.
- Сверены официальные требования Android для SpeechRecognizer, фонового микрофона и MediaProjection; документация OpenAI Realtime, Anthropic Messages API, Manus API v2.
- НЕ выполнялась диагностика живого Debian/Google Cloud VM, частных файлов планшета, ключей, внешних сетевых маршрутов или фактической оплаты API: доступа к интерактивной консоли/ADB в этой сессии нет. GitHub CI не заменяет такие проверки.
- GOLD и Kraken не трогать, ключи не переписывать и не отображать.

## Решение о реализуемости
**Да:** одно подписанное Android-приложение с живой анимированной Ланой, управляемым разговором, полезной сохранённой памятью, собственными задачами и выбранным доступом к OpenAI, Claude и Manus через защищённый сервер реализуемо на планшете Samsung.
**С оговорками:** 24/7 без единого обрыва, произвольное чтение экрана без согласия, автоматический доступ ко всем чатам ChatGPT и автономный контроль других программ без полномочий невозможны в заявленном абсолютном виде. Можно проектировать устойчивое *сервисное* поведение с явным запуском, системным уведомлением, watchdog/восстановлением, голосовой активацией (зависит от роли Android default assistant и устройства), согласием на экран и ограничениями Android.

## Что есть, а чего нет (проверка по коду, НЕ по рекламе)
| Направление | Уже реализовано | Не готово / риск |
|---|---|---|
| Android приложение | Один подписываемый пакет и обновление поверх старого с сохранением данных, последний релиз 1043 | Результат физической установки/продолжительной работы 1043 отдельно не подтверждён |
| Разговор | SpeechRecognizer → HTTP запрос → системный TTS / MP3; очереди и STOP, логика нескольких реплик | Нет настоящей low-latency потоковой аудиосессии с прерыванием речи; SpeechRecognizer не предназначен для непрерывного распознавания, Android код 11 наблюдался |
| Экран выключен | Foreground-service, частичный wakelock, несколько реплик на Samsung подтверждались | Нет доказательства 24/7, после force-stop/перезагрузки авто-микрофон ограничен Android, на долгих тестах нет устойчивой статистики |
| Память | Локальные заметки и задачи, шифрованные короткие диалоги (в конкретном режиме), отдельные утверждённые факты серверного прототипа | Нет единой долговременной памяти с датами/проектами/источниками, безопасным поиском, согласованием сохранения и сквозной синхронизацией |
| Команда | Журнал заданий и отправка запроса OpenAI API-помощнику, ручная проверка ответа | Claude и Manus не подключены, общего model-router, одинакового task schema и гарантированной долговечной server queue нет |
| Автономность | SQLite прототип heartbeat / анализ DEMO отчёта, запрет опасных действий | Не подтверждены установка этого ядра на боевой VM, долговременный серверный планировщик, циклические проверки, реальные интеграции. Не запускать live trade |
| Лицо | Портрет/логотип, состояния Слушаю/Думаю/Отвечаю | Нет настоящей синхронизации движения губ со звуком, реакций на перебивание и завершение предложения |
| Зрение | Старый ScreenCaptureService в архиве V3.3, экспериментальный URL | Нет подтверждённого безопасного авторизованного канала изображения до модели. Android требует нового разрешения на каждый сеанс MediaProjection |

| Безопасность | Сохранённая подпись, некоторые ограничения/шифрование, ручное одобрение результатов | Нужны постоянные проверки сетевых полномочий, стоимости, разрешений, резерва/отката и разделения инструментов; никакой авторизации опасных действий по одному LLM-тексту |

## Ключевая архитектура
```
Samsung LANA App
  ├─ Avatar (состояние из реального аудиодвижка / времени воспроизведения)
  ├─ Local Wake Word + VAD [только после сравнения батареи и микрофона]
  ├─ Realtime Speech WebRTC (короткоживущий токен, никаких секретов провайдеров в APK)
  ├─ Encrypted local cache + memory consent / backup / user controls
  └─ Permission-gated screen sharing (MediaProjection per approved session)
           ↕ TLS authenticated protocol with idempotent IDs
LANA Core (Debian / VM, after separate authorized deployment)
  ├─ Session Router + turn/state/latency traces (no raw private text in logs)
  ├─ Model Router: OpenAI, Claude, Manus (each key and health status independent)
  ├─ Memory v2: timestamp, source, scope, confidence, explicit save/forget controls
  ├─ Durable Task Queue, state machine, budget, retry discipline and checkpoints
  ├─ Tool Authorization: read-only by default, user approvals for external effects
  └─ Observability, watchdog, backup/restore, rollback and signed release pipeline
```

**Протокол:** одна схема Task(id, agent, status, requested_at, result_at, request_digest, user_approved_action, cost) и Memory(id, project, category, source, created_at, consent, version, content). Не переносить в модель весь разговор по умолчанию. Состояния UNKNOWN, NOT_CONFIGURED, CONNECTING, VERIFIED_AT, FAILED без фиктивного зелёного «подключено».

## Следующая поставка должна включать НЕ ОДИН, а ПАКЕТ взаимосвязанных изменений

### Блок A — разговор и личность (одна кандидатная версия, не релиз по каждой мелочи)
1. Выделить VoiceEngine интерфейс. Оставить текущий распознаватель как резерв; добавить экспериментальный потоковый путь WebRTC/Realtime. Измерять перехваты начала речи, паузы 1–1.5 сек и скорость первого звука.
2. Корректные interrupt/barge-in/STOP, аудиофокус и восстановление после пропадания Wi-Fi. Не дублировать платные API-запросы автоматически.
3. Привязать портрет, губы/индикацию и реальные фазы к аудиокадрам. Убрать фиктивные «слушаю» при отсутствии микрофона.
4. Ввести контекст-тесты (продолжение темы, краткость, юмор по ситуации, проверка фактов) без шаблонных вопросов от модели.
5. Единый экран «проверка» с успешными и неуспешными голосовыми сценариями, количеством ошибок 11 и копируемым отчётом.

### Блок B — долговременная память
1. Нормализованная схема заметок/фактов/решений/событий с источником и временем, per-project; импорт старых записей без удаления.
2. Ручное подтверждение важной памяти и явные команды просмотра/исправления; отдельный экспорт и восстановление.
3. Разделить «локальная история», «серверная память» и «история ChatGPT» в интерфейсе и в ответах.
4. Регрессионные проверки межпроектной изоляции, закрытого экрана, отказа диска и рестарта.

### Блок C — настоящая команда из трёх ИИ
1. Отдельные server adapters OpenAI, Claude Messages API и Manus API v2 (не путать подписки в приложениях с API).
2. Роутинг заданий с owner, статустаблицей, тайм-аутом и подтверждением результата; невозможность принять текст модели за реально выполненную команду.
3. Показ пользователю «что отправлено, куда, когда, сколько стоило, что проверено». Ограничить расходы/параллелизм; тестирование сначала mock без платных ключей.
4. Только после добровольного подключения провайдеров — по одному реальному дешёвому тесту, с фиксацией результата, без хранения секретов в GitHub/Android.

### Блок D — глаза и автономность
1. User-consented screen capture; ограниченный поток кадров, скрытие чувствительных областей/документов, отдельная кнопка STOP.
2. Server-owned authorized tools: read-only диагностика LANA, потом изолированные git-ветки/тесты, задания с согласованием; никакой команды на удаление данных или оплату без явного одобрения.
3. Долговечная очередь / расписание / уведомления; сохранять собственные действия в журнале, переживать серверный рестарт, не повторять опасные операции.

## Quality gates для каждого БОЛЬШОГО пакета
- План с критериями → реализация 4–6 связанных задач → самотест → внешний эмуль + реальный Samsung → исправление → журнал + точка продолжения.
- После 5 циклов/повторяющейся причины — остановить правки и пересмотреть архитектуру.
- Перед рискованной работой: резервная копия, подпись/ключ не менять, стабильную ветку/релиз не трогать, откат вперёд той же подписью.
- CI: Kotlin/Python tests, emulator data persistence, screenshot, signature compatibility, property-based tests for memory/voice and protected provider routing.
- Реальное устройство: >= 50 последовательных диалоговых реплик, >= 20 реплик после блокировки экрана (с разрешённым сервисом); проверка STOP, сети, перезагрузки (с оговорками Android), пропавших первых слов, code11 recoveries и корректности локальной памяти.
- Наблюдать 30+ минут с сообщениями о микрофоне, 99% успешных сохранений под тестовой нагрузкой; измерять median/p95 «вопрос→первый звук», а не утверждать произвольную задержку.
- Публиковать **один подписанный APK после пакета**, не отдельный APK на каждую косметическую правку.

## Блокирующие вопросы / честные границы проверки
- **Нет доступа к запущенному Debian/VM или ADB планшета:** прежде чем менять VM — безопасный только-чтение снимок процессов, диска, CPU, systemd, логов LANA; затем резервная копия и отдельно согласованный деплой. Код GitHub нельзя объявлять работающим сервером.
- Три AI через API требуют три независимые настройки и доступ/оплату; ChatGPT Plus НЕ покрывает OpenAI API автоматически.
- Android стандартный SpeechRecognizer не предназначен для непрерывной фоновой речи; альтернативы требуют собственной архитектуры, батареи и разрешений. Android может блокировать запуск микрофонного foreground-service из background и после boot.
- Запись/демонстрация экрана требует согласия пользователя на каждую сессию MediaProjection на современных Android.
- Нельзя обещать чтение всей истории ChatGPT без отдельного авторизованного механизма импорта/доступа.
