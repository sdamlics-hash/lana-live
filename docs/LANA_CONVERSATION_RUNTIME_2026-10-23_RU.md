# Общий модуль диалога и озвучки

## Что перенесено
- Обычный запрос разговора, его сетевой worker, принятый ответ, запись краткого контекста и оба вида озвучки теперь принадлежат Service. В запросе фиксируются сервер, учётные данные, conversation ID и явно выбранные заметки; View/Activity в конфигурации нет.
- LanaConversationRuntime — чистый автомат состояний THINKING → PREPARING_VOICE → SPEAKING → READY либо ERROR/STOPPED. Частичные результаты распознавания по-прежнему не вызывают сервер.
- Runtime управляет одной текущей операцией, поколениями и отменой. Поздний ответ после STOP не записывается в контекст и не запускает голос. Повторные callback не дают повторной озвучки или записи.
- Транспорт и облачный голос используют по одному worker с очередью не более двух ожидающих операций. После сбоя нет автоматической повторной отправки платного запроса. Отмена локального ожидания не гарантирует остановку уже начатого вычисления на сервере.
- Принятый текст записывается в историю до озвучки. Отказ сохранения отражается отдельно; текст остаётся в текущем снимке runtime и показывается без заявления об успешной долговременной записи.
- Облачный MP3 и системный TTS обслуживает один сервисный адаптер. Временный файл удаляется при завершении, ошибке, STOP и закрытии сервиса. Поздние аудиоданные после отмены не создают файл и не играют.
- Учтены ожидание системного TTS (8 секунд), подготовка проигрывателя (10 секунд) и незавершённая озвучка (120 секунд). Ошибка звука оставляет полный ответ доступным текстом.
- Перед фактическим воспроизведением запрашивается аудиофокус; при отказе или потере звука озвучка прекращается без автоматического повтора. Устаревший callback другого поколения игнорируется.
- Интерфейс получает снимки состояний и обновляет историю из общего хранилища. Настройки голоса по-прежнему доступны; Activity TTS используется только для списка системных голосов, не для разговора.
- Переключение вида озвучки отменяет текущий вывод и возвращает включённый сеанс к слушанию без повторной отправки вопроса.
- Явно включённый foreground-режим может завершить уже начатый обычный ответ/озвучку после отвязки Activity. Микрофон при отвязке освобождается. После завершения без клиента сервис снимает уведомление и останавливается.
- STOP из уведомления и удаление приложения из списка недавних останавливают запрос/звук. При возвращении интерфейс не повторяет старый запрос. Восстановление памяти и новый разговор блокируются, пока текущий ответ ещё выполняется.

## Что ещё не перенесено
Разбор голосовых локальных команд и переход к следующему вопросу пока запускает Activity. API-задания вкладки «Команда» также ещё используют прежний путь. Поэтому непрерывная самостоятельная беседа без экрана, перезапуск после убийства процесса и режим 24/7 не объявляются готовыми.

## Проверки
Локально прошли 86 Python-тестов и 10 subtests. Чистые Kotlin/JVM-тесты: 86. Новые проверки покрывают STOP до/после ответа, устаревший сетевой результат, повторный callback, смену наблюдателя без повтора запроса, текстовый режим, ошибку сохранения, исключения транспорта/голоса и синхронные callback. AndroidKeyStore, реальный звук, аудиофокус, Samsung и уход/возврат Activity требуют отдельной проверки устройства.

Общая Android-сборка проверяет совместимость Service, Binder, TTS и MediaPlayer; её результат сверяется по последнему коммиту.

## Основание Android
https://developer.android.com/media/optimize/audio-focus — запрашивать фокус непосредственно перед воспроизведением, прекращать/приостанавливать звук при потере и освобождать после завершения; ограничения API 35 для фонового запроса фокуса.
