# Диагностика контекста и ожидания ответа

В PR #25 вместе с общей инструкцией диалога добавлены измерения Android-клиента. Журнал сервисного диалога содержит только queue_ms (ожидание рабочего потока), request_ms (создание запроса, сеть и получение ответа целиком), local_pairs (число полных пар локального контекста) и result=ok/error. Это не измерение вычислений модели на сервере. Последние шесть полных пар из локального контекста уходят в legacy-протокол согласно существующему ограничению; local_pairs может достигать восьми. Содержимое реплик, адрес и ключ не журналируются.

Диагностика общая для обычного и фонового режима, поскольку оба используют один Service-owned transport. Отменённый запрос не публикует позднее измерение. Ошибка диагностического обработчика не блокирует ответ. Метка экрана заменена с «Ожидание ответа сервера» на «Запрос и получение ответа»: прежнее название приписывало серверу также локальное ожидание и передачу данных.

Никакие дополнительные сетевые запросы или автоматические повторы не добавлены. Подключение другого ИИ и двусторонний канал с ChatGPT этим изменением не создаются. Утверждать улучшение скорости или понимания по этим измерениям нельзя: для этого нужен новый фактический диалог на Samsung. Живой серверный тест с недоступным ключом не повторялся.
