# LANA: автономное ядро — экспериментальная версия

Статус: изолированный прототип на отдельной ветке GitHub. Не установлен на Google Cloud VM, не подключён к планшетному приложению Ланы или брокерам.

## Что проверено тестами

- Очередь SQLite: сохранение между перезапусками, журнал событий и атомарный захват задания.
- Идемпотентность: повторный запрос с тем же ключом и теми же данными не создаёт дубль; конфликтующие данные блокируются.
- Локальный HTTP-интерфейс с обязательным Bearer-токеном (не меньше 32 символов).
- Чтение статуса и результата задачи без исходных данных.
- Только два разрешённых офлайн-задания: heartbeat и trade_report.
- Trade report обрабатывает только переданные закрытые DEMO-сделки; не запрашивает данные у брокера.
- Запрет операций send_email, real_trade, payment, run_shell_command, а также прослушивания на публичном адресе.
- Все тесты запускаются в CI на GitHub Actions, независимо от старой сборки Android.

## Как проверить локально

Из корня проекта:

    python -m unittest discover -s tests -v
    python -m lana_core.cli --db /tmp/lana_tasks.sqlite3 heartbeat
    python -m lana_core.cli --db /tmp/lana_tasks.sqlite3 run-once

Чтобы проверить HTTP-интерфейс, создайте собственный длинный случайный секрет. Не вписывайте его в код и не загружайте в публичный GitHub. В двух разных терминалах используйте одну базу:

    export LANA_API_TOKEN="$(python -c 'import secrets;print(secrets.token_urlsafe(48))')"
    python -m lana_core.api --db /tmp/lana_tasks.sqlite3
    python -m lana_core.cli --db /tmp/lana_tasks.sqlite3 daemon

Проверка доступа из третьего терминала, запущенного на том же компьютере:

    curl -s http://127.0.0.1:8787/healthz
    curl -s -H "Authorization: Bearer $LANA_API_TOKEN" http://127.0.0.1:8787/v1/status
    curl -s -X POST http://127.0.0.1:8787/v1/tasks \
      -H "Authorization: Bearer $LANA_API_TOKEN" \
      -H "Content-Type: application/json" \
      -d '{"kind":"heartbeat","payload":{},"idempotency_key":"test-1"}'

HTTP-маршруты:
- GET /healthz (не конфиденциальный локальный статус без токена)
- GET /v1/status (токен обязателен)
- POST /v1/tasks (токен обязателен; kind, payload, optional idempotency_key)
- GET /v1/tasks/{task_id} (токен обязателен; состояние, результат и ошибки)

## Ограничения

Этот HTTP-сервер намеренно принимает соединения только с 127.0.0.1. Прямое подключение с планшета не заработает без отдельного защищённого сетевого шлюза. Нельзя просто менять адрес на 0.0.0.0: HTTP не шифрует токен. Перед сетевым доступом нужны TLS/VPN, ограничение входящих соединений, отдельные ключи и аудит.

Сейчас нет интеграции с Android V3.3, OpenAI API, Gmail, Telegram, cTrader/FxPro или инструментами компьютерного управления. Нет сервиса, самостоятельно выбирающего задачи. Команда daemon только извлекает уже поставленные локальные задания.

Никакие рабочие роботы или живые деньги не затрагиваются. Система не запущена круглосуточно, не протестирована на VM.

## Проверка Android V3.3 (21.10.2026)

Исходный ZIP Android V3.3 разобран, найдены файлы MainActivity.kt и ScreenCaptureService.kt, а также Manifest, Gradle и XML-макет.

- Голос в MainActivity реализован через Android SpeechRecognizer и TextToSpeech. Ответы пока шаблонные, полноценного LLM-вызова нет. Хранится до 30 строк локальной истории.
- ScreenCaptureService по отдельному разрешению MediaProjection делает JPEG и пытается отправлять его на введённый HTTPS-адрес, путь /frame. Эта функция не связана с новой очередью задач.
- В текущем коде отправки /frame не видно заголовка авторизации: не подключать его к публичному серверу без дополнительной проверки и защиты.
- Существующий локальный API намеренно НЕ поддерживает /frame и не принимает скриншоты. Не следует считать функции зрения и памяти готовыми.

Следующий шаг: подготовить отдельную тестовую Android-сборку V3.4 с защищённым подключением к серверу и проверкой /v1/status, затем реализовать диалог через OpenAI API и только после этого — поэтапный защищённый канал для изображений. Приложение на планшете и главную ветку не изменять до тестирования.
