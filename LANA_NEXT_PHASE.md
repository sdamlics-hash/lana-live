# LANA — development checkpoint (2026-10-10)

## Verified on Samsung tablet
- LANA TEST 3 installed separately (`ai.dreibus.lanalive.preview3`).
- Russian speech recognition produces `Вы:` entries.
- App produces `Лана:` entries and Android TextToSpeech is audible (confirmed by user).
- Current reply is **hard-coded** (`Да, я здесь. Слушаю тебя.`), not generated by an LLM.
- Screen button has a placeholder server URL; no live visual understanding is proven.

## Next implementation target: actual conversational AI
1. Define authenticated HTTPS backend with `/v1/lana/chat` accepting `session_id`, user text and limited conversation context, returning assistant text; no API key embedded in APK.
2. Add a network client to Android app with explicit connectivity/error states; keep microphone and TTS usable offline as a fallback.
3. Route each recognized utterance through backend and speak the generated response; ensure speaking does not trigger speech recognition feedback loops.
4. Keep an on-device rolling conversation history and explicit privacy controls; never transmit screenshots without an on-screen permission action.
5. Introduce a durable Android signing identity for future updates (secure CI secret), fixed application ID, and clear visible build/version marker. Do not create LANA TEST 4, 5, etc. merely to work around mismatched debug signatures.
6. Automated tests for Russian recognition callbacks, backend timeout, TTS failures, pause/resume and safe action confirmations.

## Acceptance tests
- User says an arbitrary question in Russian; LANA answers relevant to the question, not a fixed phrase.
- User can ask a follow-up without manually typing or uploading a screenshot.
- No claims of 24/7 background operation until Android background microphone and power-management behavior are verified.
- Sensitive actions (money, deletion, sending messages) require explicit confirmation.

## Constraints
- Android screen-capture requires user consent through MediaProjection.
- No silent/unlimited device surveillance or unsafe secret handling.
- Avoid asking the user to repeatedly install APKs for changes that can be tested in CI.
