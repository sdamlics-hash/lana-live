# Проверка обновления без потери данных

Проверяются уже собранные артефакты V3.9(run39617281734) и V4.0(run39642156635), не приложение на настоящем Samsung. Android SDK apksigner проверяет подлинность подписей обоих APK; aapt читает package/versionCode/versionName. Отчёт сравнивает открытые SHA256-отпечатки сертификатов, package и рост versionCode. Секретные ключи не создаются, не читаются, не меняются и не публикуются.

Для release-политики одинаковый либо меньший versionCode блокирует выпуск даже при совпадении сертификата. Это требование выпуска, не утверждение, что adb обязательно запрещает равный versionCode. Ротация ключей/подписи предшественников автоматически не подтверждается.

Эмулятор устанавливает V3.9, создаёт контролируемые задачу/заметку, проверяет сохранность, затем выполняет adb install -r V4.0. При разных текущих сертификатах проверка ожидает явный INSTALL_FAILED_UPDATE_INCOMPATIBLE; после отказа проверяет прежние записи. При совпадении подписей проверяет успешную замену и записи. Приложение никогда не удаляется ради успешной установки. Весь опыт идёт на новом тестовом эмуляторе, не на устройстве пользователя.

Успех workflow означает, что проверка завершилась, а не что APK можно ставить на Samsung. Решение читается в update-report.json: block_reasons/device_update_test/baseline_records_preserved. samsung_install_ready всегда false: подпись и данные настоящего установленного приложения ещё не сверены. Для постоянных обновлений нужен контролируемый постоянный ключ подписи и повышаемый versionCode; нельзя просто заменить ключ старого установленного APK. Сначала определить фактическое приложение и его сертификат, затем решить безопасный переход/резервирование данных. Никогда не выкладывать private keystore в public git/Actions artifact.
