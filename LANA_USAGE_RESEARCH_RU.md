# LANA — квоты вызовов модели и ограничения Android

**Статус:** код для тестовой ветки; ещё не развёрнут на VM, внешний OpenAI API не оплачивался и не вызывался во время тестов.

## Контроль запросов
- До внешнего запроса к модели атомарно фиксируется попытка в SQLite.
- Стандартное ограничение: **100 попыток в день на всю Лану** и **30 попыток в час на один идентификатор разговора**.
- Настройка только в среде сервера: `LANA_CHAT_DAILY_MAX` и `LANA_CHAT_HOURLY_MAX`, целые числа от 1 до 10000. Требуется ответственный подбор значений перед запуском.
- При превышении сервер возвращает HTTP 429; диалог не теряет уже сохранённую историю.
- Лимиты сохраняются после рестарта и защищены одной транзакцией SQLite, включая параллельные запросы.
- **Не путать с денежным лимитом!** Десять длинных запросов могут стоить дороже ста коротких. Для настоящей финансовой защиты требуются дополнительно бюджетные ограничения на стороне API и мониторинг расхода.
- Для защиты от сетевой петли считаем даже попытку, если API затем ответил ошибкой или истёк таймаут.

## Что исследовано по Android
В документации Android стандартный `SpeechRecognizer` прямо назван неподходящим для непрерывного распознавания — оно может расходовать заряд и передавать звук на внешние серверы. Поэтому тестовый цикл распознавания не является гарантией «всегда слушает 24/7».

На Android 14+ для фонового микрофона есть ограничения `RECORD_AUDIO` / `FOREGROUND_SERVICE_MICROPHONE` и запуска foreground service из фонового состояния. Будущий режим «Лана, ты тут?» при выключенном экране потребует отдельной архитектуры, явного согласия пользователя и реального испытания на Samsung.

Официальные источники:

- https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start
- https://developers.openai.com/api/docs/guides/text-to-speech
